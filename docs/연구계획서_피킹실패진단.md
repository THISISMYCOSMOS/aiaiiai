# 연구계획서

## 1. 과제 개요

| 항목 | 내용 |
|---|---|
| 과제명(가제) | 피킹 실패를 진단하고 기록해 개선하는 로봇팔 |
| 소속 | 정보융합학부 |
| 참여 인원 | 박성준, 윤태영, 김평화, 이영재 (4명) |

## 2. 연구 방향

로봇팔이 물건을 집다 실패하면 원인을 진단해 방법을 바꿔 다시 집고, 그 실패를 기록으로 남겨 다음에는 처음부터 실패를 피하게 만들고자 합니다.

예를 들어 로봇이 컵을 집다가 미끄러져 놓쳤다고 하겠습니다. 시스템은 카메라 영상과 그리퍼 센서 기록을 보고 원인을 "미끄러짐"으로 진단하고, 더 깊게 잡는 방식으로 다시 시도합니다. 이 실패와 대응은 기록으로 남습니다. 다음에 비슷한 컵을 만나면 로봇은 기록을 참고해 처음부터 깊게 잡습니다.

```
 인식 ──> 실패 예측 ──> 집기 ──> 결과 확인 ──(성공)──> 다음 물건
             ↑                       │
             │                     (실패)
             │                       ↓
           기록 <── 재시도 <──── 원인 진단
```

로봇팔은 실제 장비로 구현하되, 연구의 중심은 실패 원인을 진단하고 재시도 방법을 정하는 판단 과정입니다. 블록체인은 기록이 등록된 뒤에 바뀌지 않았는지 확인하는 보조 수단으로 씁니다.

## 3. 선행연구와 차별점

| 선행연구 | 내용 |
|---|---|
| REFLECT (CoRL 2023) | LLM이 로봇의 실패를 설명하고, 해당 작업 안에서 바로잡습니다. |
| Agentic RAG-VLM (arXiv 2026) | VLM이 실패 유형을 진단하고 다시 시도하며, 물체 특성별로 성공한 집기 전략을 다시 씁니다. 결과는 시뮬레이션에서 얻었습니다. |
| 운영 기록 기반 실패 유형 발견 (arXiv 2506.06570) | 현장 운영 기록에서 실패 유형을 자동으로 찾아 묶습니다. |

LLM으로 실패를 진단해 다시 시도하는 연구는 이미 있습니다. 저희가 차별점으로 생각하는 것은 두 가지입니다.

1. **실제 로봇팔에서 진단이 맞는지 측정합니다.** 원인이 정해진 실패를 일부러 만들어 LLM의 진단과 비교합니다. REFLECT도 실패 설명을 평가했기 때문에, 이 점이 얼마나 새로운지는 더 확인하려고 합니다.
2. **같은 물건의 실패 기록을 다음 시도에 씁니다.** 기존 연구는 물체 범주 단위로 성공한 전략을 다시 썼습니다.

## 4. 연구 방법

시스템은 2절의 흐름대로 동작합니다. 물체를 인식해 집기 후보를 만들고, 과거 실패 기록으로 실패 확률이 낮은 후보를 고른 뒤 집습니다. 실패하면 LLM·VLM이 영상과 센서 기록으로 원인(미끄러짐, 가림, 위치 오차, 오인식 등)을 고르고, 원인에 맞게 각도나 집는 지점을 바꾸어 다시 집습니다.

기록 원본은 서버에 두고, 기록의 지문(해시)만 블록체인에 올립니다. 로봇 동작은 블록체인 기록을 기다리지 않습니다. 이 방식은 등록 뒤의 변경만 탐지하며, 처음부터 잘못 남은 기록이나 등록 전 누락은 막지 못합니다.

## 5. 실험 계획

| 실험 | 비교 | 평가 지표 |
|---|---|---|
| 재시도 방식 | 같은 동작 반복 vs 원인에 맞춘 재시도 | 최종 성공률, 시도 횟수, 소요 시간 |
| 진단 정확도 | LLM·VLM 진단 vs 정답 원인 | 원인별 정확도 |
| 기록 재사용 | 과거 기록 미사용 vs 사용 | 같은 물건의 첫 시도 성공률 |
| 기록 무결성 | 일반 저장 vs 블록체인 지문 저장 | 변경 탐지 여부, 추가 지연 |

원인별 사례를 고르게 모으려고 물건 겹쳐 놓기, 미끄러운 물건 섞기, 그리퍼 위치 틀리게 하기 등으로 실패를 일부러 만듭니다. 재시도 실험은 두 방식에 같은 최대 재시도 횟수를 적용하고, 기록 재사용 실험은 미리 모아 고정한 기록으로 같은 물건·같은 배치에서 비교합니다.

## 6. 역할 분담

피킹 한 번을 단계별로 나누어 맡고, 로봇팔과 그리퍼 제어는 네 명이 함께 합니다.

- **비전 (윤태영):** 물건을 찾아 집기 후보를 만들고, 집은 뒤 성공·실패를 판정합니다.
- **데이터 (김평화):** 과거 실패 기록으로 후보마다 실패 확률을 매기고, 물건별·원인별로 실패가 몰리는 곳을 분석합니다.
- **서버 (이영재):** 전체 흐름을 관리하고, LLM·VLM으로 실패 원인을 진단해 재시도 방법을 정합니다.
- **블록체인 (박성준):** 기록 형식과 저장을 관리하고, 기록의 지문을 블록체인에 올려 변경 여부를 확인합니다.

## 7. 정하고 있는 주제

적용 분야는 아래 네 가지 가운데에서 정하고 있습니다. 어느 분야든 2절의 흐름은 같습니다.

- **이커머스 주문 포장:** 상품을 상자에 담다 빠뜨리면 누락이 되고, 담았다는 기록이 분쟁 증거가 됩니다.
- **재활용 선별:** 구겨지거나 젖은 페트병·캔을 흡착 그리퍼로 골라내는 일이라 실패 원인이 다양합니다.
- **약병 검사·배정:** 라벨이 가려진 약병을 돌려 다시 읽어야 하는 재시도 상황이 분명합니다.
- **비정형 물체 피킹:** 흩어진 물건 가운데 지정한 것을 집는 일입니다.

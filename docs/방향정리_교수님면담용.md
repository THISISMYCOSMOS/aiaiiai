# 피킹 실패를 진단하고 기록하는 로봇팔 (가제)

- 소속: (기입)
- 팀원: 박성준, 윤태영, 김평화, 이영재
- 작성일: 2026년 11월 6일
- 연락처: (기입)

## 1. 연구 방향

로봇팔이 물건을 집다 실패하면 카메라와 센서 기록으로 원인을 진단하고, 방법을 바꿔 다시 집습니다. 실패와 진단 결과는 기록으로 쌓아 다음 피킹에 씁니다. 로봇팔은 실제로 구현하지만, 연구의 중심은 판단 과정입니다. 블록체인은 기록이 나중에 바뀌지 않았는지 확인하는 보조 수단입니다. 적용 도메인, 그리퍼 종류(집게형·흡착형), 로봇팔 기종은 아직 정하지 않았습니다.

## 2. 동작 흐름

1. **인식:** 사전학습 비전 모델(VFM)로 물건을 찾고 집기 후보를 만듭니다. 물건마다 새로 학습시키지 않습니다.
2. **실패 예측:** 쌓인 기록에서 비슷한 물건과 상황의 과거 실패를 찾아, 실패 확률이 낮은 후보부터 고릅니다.
3. **집기:** 로봇팔이 물건을 집습니다.
4. **결과 확인:** 카메라, 그리퍼 센서, 무게로 물건이 집혔는지 봅니다.
5. **실패 진단:** LLM·VLM이 영상과 센서 기록을 보고 원인을 고릅니다. 미끄러짐, 가림, 위치 오차, 오인식 같은 원인입니다.
6. **재시도:** 원인에 맞춰 각도나 집는 지점을 바꾸거나, 주변 물건을 먼저 치웁니다.
7. **기록:** 실패 장면, 진단, 바꾼 전략, 결과를 남깁니다. 이 기록은 다음 피킹의 실패 예측에 다시 쓰입니다.

## 3. 배경

- 팀원이 로보월드 전시회에서 VFM 기반 피킹 로봇팔을 봤습니다. 물건이 3개뿐인데도 연속으로 못 잡거나 잡다가 놓치는 일이 잦았습니다. 현장 관계자는 이런 오류를 따로 로그로 모으지 않는다고 했습니다. 공식 자료가 아닌 팀원 관찰입니다.
- Amazon 물류 로봇 연구는 운영 데이터 약 39만 5천 건(그중 실패 5만 9,646건)으로 집기 성공 예측 모델을 학습시켰습니다. 실패 기록이 개선 재료로 쓰인 사례입니다. 학습을 위해 실패 비중을 일부러 높인 데이터라서 운영 실패율로 읽으면 안 됩니다.

## 4. 선행연구와 차이

| 선행연구 | 한 것 |
|---|---|
| REFLECT (CoRL 2023) | 로봇 경험을 요약해 LLM이 실패를 설명하고, 그 작업 안에서 고친다 |
| Agentic RAG-VLM (arXiv 2026) | VLM이 14가지 실패 유형으로 진단하고 최대 3번 다시 시도한다. 물체 특성별로 성공한 집기 전략을 찾아 다시 쓴다. 성공률 78.3%는 실제 로봇이 아닌 분석적 시뮬레이션 결과다 |
| 운영 기록에서 실패 유형 찾기 (arXiv 2506.06570) | 현장 운영 기록에서 실패 유형을 자동으로 찾아 묶고, 데이터 수집과 실패 감시에 쓴다 |

LLM의 실패 진단과 재시도, 성공 전략 재사용, 운영 기록 분석은 이미 연구돼 있습니다. 저희가 차별점으로 보는 것은 아래 두 가지입니다. 이 정도면 연구가 되는지 여쭙고 싶습니다.

1. **진단 정확도 측정:** 원인이 정해진 실패를 일부러 만들어 LLM 진단과 맞춰 봅니다. 그리퍼 목표 위치를 옮기면 정답은 위치 오차이고, 물건 위에 다른 물건을 올리면 정답은 가림입니다. 자연스럽게 생긴 실패는 사람이 영상을 보고 원인을 붙입니다. 관측만으로 원인을 가를 수 없으면 미확정으로 둡니다. REFLECT도 RoboFail 데이터셋으로 실패 설명을 평가했으므로, 실제 로봇팔의 피킹 실패에서 진단을 재는 것이 얼마나 새로운지는 더 확인해야 합니다.
2. **같은 물건의 실패 기록 재사용:** 쌓인 실패·진단 기록으로 같은 물건의 첫 시도 성공률이 오르는지 봅니다. 앞의 연구는 물체 범주별 성공 전략 재사용까지 다뤘습니다.

선행연구 비교는 초록과 일부 본문만 읽고 한 것입니다.

## 5. 블록체인의 역할

기록 원본은 서버에 두고 지문(해시)만 블록체인에 올립니다. 로봇 동작은 블록체인 기록을 기다리지 않습니다. 이렇게 하면 등록 뒤에 원본이 바뀌었는지는 잡을 수 있지만, 처음부터 틀린 기록, 등록 전에 빠진 기록, 원본 삭제는 막지 못합니다. 로봇 공급사와 현장 운영사가 실패 책임을 따질 때 함께 확인할 수 있는 기록이 필요할 것으로 보지만, 실제 수요는 확인하지 못했습니다.

## 6. 실험

| 비교 | 보는 값 |
|---|---|
| 같은 동작 반복 재시도 vs 원인에 맞춘 재시도 | 최종 성공률, 성공까지 시도 횟수, 걸린 시간 |
| LLM 진단 vs 정답 원인 | 진단 정확도 |
| 과거 기록 사용 전 vs 후 | 같은 물건의 첫 시도 성공률 |
| 일반 저장 vs 블록체인 지문 저장 | 등록 후 변경 탐지, 추가 지연 |

실패는 일부러도 만듭니다. 물건 겹쳐 놓기, 미끄러운 물건이나 비슷한 물건 섞기, 그리퍼 위치 틀리게 하기 등입니다.

## 7. 역할 분담

피킹 한 번을 시간 순서로 나누어 맡습니다. 로봇팔과 그리퍼를 움직이는 로봇제어는 네 명이 같이 합니다.

**비전 (윤태영): 무엇이 어디 있고, 집혔는가.** 카메라 영상에서 물건을 찾고, 어느 부분을 어떤 각도로 잡을지 집기 후보를 만듭니다. 집은 뒤에는 물건이 그리퍼에 있는지, 떨어졌는지를 판정하고, 실패했다면 실패 순간의 영상을 서버로 넘깁니다. 인식 정확도와 성공·실패 판정 정확도를 숫자로 보이면 끝입니다.

**데이터 (김평화): 이번에는 처음부터 어떻게 덜 실패할까.** 비전이 집기 후보를 넘기면, 쌓인 기록에서 비슷한 물건과 상황의 과거 실패를 찾아 후보마다 실패 확률을 매깁니다. 비슷한지는 VFM이 뽑은 이미지 특징으로 판단합니다. 또 쌓인 기록을 물건별, 원인별로 정리해 어디서 실패가 몰리는지 분석합니다. 이 분석은 실패 예측의 근거가 되고, 재시도 방법을 고를 때도 참고 자료가 됩니다. 과거 기록을 쓸 때가 안 쓸 때보다 첫 시도 성공률이 오르는지 보이면 끝입니다.

**서버 (이영재): 왜 실패했고, 어떻게 다시 할까.** 인식, 실패 예측, 집기, 결과 확인, 진단, 재시도가 순서대로 돌도록 전체 흐름을 관리합니다. 실패하면 영상과 센서 기록을 LLM·VLM에 넣어 원인을 고르게 하고, 원인에 맞는 재시도 방법을 골라 로봇에 지시합니다. 원인이 정해진 실패를 일부러 만들어 진단이 맞았는지 검증하고, 실험 반복과 조건 관리도 맡습니다. 진단 정확도와, 같은 동작 반복보다 원인에 맞춘 재시도가 나은지를 보이면 끝입니다.

**블록체인 (박성준): 기록이 남고, 안 바뀌었는가.** 모든 단계의 결과를 정해진 형식으로 저장합니다. 각 역할이 필요한 항목을 요청하고, 형식은 블록체인 담당이 관리합니다. 기록 한 건마다 지문(해시)을 만들어 블록체인에 올리고, 나중에 원본과 대조하는 도구를 만듭니다. 등록 뒤 기록을 고치면 탐지되는 것과, 기록 때문에 늘어난 시간을 보이면 끝입니다.

## 8. 검토 중인 적용 분야

적용 분야는 아직 정하지 않았고, 아래 네 가지를 검토하고 있습니다. 어느 분야든 위의 흐름은 같습니다.

- **이커머스 주문 포장:** 상품을 상자에 담다 빠뜨리면 곧 누락이 되고, 담았다는 기록이 분쟁 증거가 됩니다.
- **재활용 선별:** 구겨지고 젖고 깔린 페트병·캔을 흡착 그리퍼로 골라내는 일이라 실패 원인이 다양합니다.
- **약병 검사·배정:** 라벨이 가려진 약병을 돌려서 다시 읽는 재시도 상황이 분명합니다.
- **비정형 물체 피킹:** 흩어진 물건 중 지정한 것을 집는 일로, 전시회에서 본 실패 상황과 가장 가깝습니다.

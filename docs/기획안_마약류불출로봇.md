# 기획안: 믿을 수 있는 마약류 불출 로봇

로봇이 마약류 약병을 꺼내 운반함에 담는 과정을 대상으로 합니다. 로봇이 스스로 남긴 기록을 그대로 믿지 않고, 외부 카메라와 저울로 확인한 증거와 대조합니다. 그리고 그 기록을 여러 기관이 함께 갖는 블록체인에 남깁니다. 이렇게 해서 실수나 조작이 생겼을 때 어느 단계에서 왜 생겼는지 찾아내는 것이 목표입니다.

- 팀: 4명 (컴퓨터비전, 로봇제어, 블록체인, 서버)
- 마감: 2027년 7월

## 1. 왜 이 문제인가

- 병원에서 마약류 기록과 실물이 맞지 않는 일이 반복됩니다. 2026년 3월 식약처가 프로포폴을 쓰는 의료기관 30곳을 점검했는데, 17곳에서 위반이 나왔습니다. 그중 9곳은 시스템에 보고한 재고와 실제 재고가 달랐습니다.
- 2018년부터 2023년까지 도난·분실 등 마약류 사고 17,673건 중 90%가 병원·의원에서 일어났습니다.
- 로봇이 스스로 하는 검사도 틀릴 수 있습니다. 조제 로봇의 무게 검사나 라벨 검사가 틀려서 잘못된 약이 통과될 수 있다는 이유로 FDA 리콜이 여러 번 있었습니다.
- 그래서 로봇을 쓰는 병원도 마약류는 로봇에 맡기지 않고 직원이 직접 옮기는 경우가 있습니다.

정리하면, 로봇이 "잘 했다"고 말하는 것만으로는 부족하고, 다른 사람도 확인할 수 있는 증거가 필요합니다.

## 2. 무엇을 만드나

불출 한 건은 다음 순서로 진행됩니다.

1. 처방이 들어오면 보관함이 열립니다.
2. 로봇팔이 약병을 집어 운반함으로 옮겨 놓습니다.
3. 각 단계마다 세 가지 기록이 따로 남습니다.
   - 로봇 보고: 로봇이 "무엇을 집었고 어디에 놓았다"고 말하는 기록
   - 외부 카메라: 로봇과 별개의 장치가 찍은 영상
   - 저울: 운반함 무게
4. 서버가 세 기록을 대조해 정상인지, 문제가 있다면 원인이 무엇인지 판정합니다.
5. 기록의 지문(해시)을 블록체인에 올립니다. 블록체인은 약제부, 병동, 감독기관이 함께 갖는 기록장입니다. 한 기관이 혼자 기록을 고칠 수 없습니다.

## 3. 연구 질문 (담당별)

| 담당 | 연구 질문 | 쉽게 말하면 |
|---|---|---|
| 컴퓨터비전 (RQ1) | 로봇과 독립된 카메라로 집기·놓기·떨어뜨림을 얼마나 정확히 확인할 수 있는가? | 카메라가 로봇의 행동을 증인처럼 확인할 수 있는가 |
| 로봇제어 (RQ2) | 로봇이 자기 센서(그리퍼 전류·위치)만으로 자기 실패를 얼마나 알아채고 보고하는가? | 로봇의 자기 보고를 어디까지 믿을 수 있는가 |
| 블록체인 (RQ3) | 어떤 기록 방식이 사후 수정, 내부자 조작, 옛 영상 재사용을 막으면서 작업을 느리게 하지 않는가? | 전자서명만으로 충분한가, 블록체인이 꼭 필요한가 |
| 서버 (RQ4) | 세 기록이 서로 어긋날 때 원인을 얼마나 정확히 가려내는가? | 사고가 나면 누구 탓인지 찾을 수 있는가 |

서버가 가려낼 원인은 네 가지입니다.

| 원인 | 예시 |
|---|---|
| 인식 오류 | 로봇은 A를 집었다고 하는데 카메라에는 B가 보인다 |
| 제어 실패 | 로봇은 놓았다고 하는데 카메라에 떨어지는 장면이 보이고 무게가 그대로다 |
| 거짓 보고 | 로봇은 완료라고 하는데 카메라와 저울 모두 개수가 모자란다 |
| 기록 변경 | 나중에 저장된 기록이 블록체인에 올린 지문과 다르다 |

## 4. 무엇을 보여 줄 것인가

검증할 가설은 세 가지입니다.

1. 카메라와 저울을 더하면, 로봇 기록만 쓸 때보다 떨어뜨림과 거짓 보고를 훨씬 잘 잡는다.
2. 전자서명은 서명 키를 가진 내부자가 기록 전체를 다시 쓰면 잡지 못하지만, 블록체인은 잡는다. 이것이 블록체인을 쓰는 이유입니다.
3. 작업 단위로 묶어 기록하면, 단계마다 기록할 때보다 작업이 덜 느려지고 탐지율은 거의 같다.

실험 방법은 다음과 같습니다. 잘못 집기, 떨어뜨림, 두 개 집기, 거짓 완료 보고, 기록 수정, 내부자 조작, 옛 영상 재사용 같은 오류를 종류별로 30번 이상 일부러 일으킵니다. 그리고 로봇 기록만, 외부 증거 추가, 전자서명 추가, 블록체인 추가의 네 구성으로 결과를 비교합니다.

## 5. 하지 않는 것

- 더 좋은 인식 모델이나 제어 알고리즘을 새로 만들지 않습니다. 각 기술은 행동을 확인하는 데 씁니다.
- 실제 마약류는 쓰지 않고 모형 약병을 씁니다.
- 기록의 법적 효력이나 인증은 다루지 않습니다.

## 6. 일정과 우선순위

| 기간 | 할 일 | 다 됐다고 보는 기준 |
|---|---|---|
| 11~12월 | 역할별 환경 준비, 기록 형식과 오류 목록 확정 | 기록 형식 문서와 오류 목록에 4명이 합의한다 |
| 1~2월 | 담당별 단독 동작 | 집기 성공률, 인식 정확도, 블록체인 기록, 서버 판정을 각각 숫자로 보여 준다 |
| 3~4월 | 하나로 연결 | 정상 불출 한 건이 증거와 함께 기록되고 판정된다 |
| 5~6월 | 오류 주입 실험 | 네 구성 × 오류 종류별 결과표가 나온다 |
| 7월 | 결과 정리와 발표 | 보고서와 발표 자료를 제출한다 |

시간이 모자라면 아래 순서로 뒤에서부터 줄입니다.

1. 정상 불출과 증거 기록 (반드시 함)
2. 외부 증거 대조로 오류 원인 판정 (가설 1, 반드시 함)
3. 전자서명과 블록체인 비교 (가설 2, 반드시 함)
4. 작업 단위와 단계 단위 기록 비교 (가설 3)
5. 옛 영상 재사용 탐지
6. 판정 규칙을 학습 모델로 바꿔 비교

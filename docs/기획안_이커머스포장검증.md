# 기획안: 믿을 수 있는 주문 포장 로봇

로봇팔이 주문 상품을 집어 상자에 담고 봉인하는 과정을 대상으로 합니다. 로봇이 스스로 남긴 기록을 그대로 믿지 않고, 외부 카메라와 저울로 확인한 증거와 대조합니다. 그리고 그 기록의 지문을 판매자·물류센터·플랫폼이 함께 갖는 블록체인에 남깁니다. 누락이나 오배송 분쟁이 생겼을 때 어느 단계에서 왜 생겼는지, 누구의 말이 맞는지 증명하는 것이 목표입니다.

- 팀: 4명 (컴퓨터비전, 로봇제어, 블록체인, 서버)
- 마감: 2027년 7월

## 1. 왜 이 문제인가

구매자가 "상자에 이어폰이 없었다"고 신고합니다. 판매자는 포장을 물류센터에 맡겼고, 물류센터는 "정상 출고했다"고 답합니다. 판매자가 포장 영상을 내도 구매자는 "찍은 뒤에 뺐을 수 있다"고 반박합니다. 결국 누구의 실수인지, 누가 거짓말을 하는지 아무도 증명하지 못합니다.

- 수량 부족 분쟁에서는 개봉 영상만으로 부족하고 주문 내역, 포장 상태, 송장 무게, 출고 기록을 함께 맞춰야 한다는 법률 안내가 있습니다.
- 판매자 커뮤니티에서는 포장 전 사진이 있어도 "찍은 뒤에 뺐을 수 있다"는 반론이 실제로 나옵니다. 기록을 만든 쪽이 그 기록을 고칠 수 있으면 증거가 되지 못합니다.
- 물류업계는 주문 정확도 목표를 99.5% 이상으로 잡지만, 실제로는 96~98%에 머문다는 업계 자료도 있습니다.

정리하면, 영상과 무게는 이미 증거로 쓰이고 있습니다. 부족한 것은 그 증거가 언제 누가 만들었고 나중에 바뀌지 않았다는 보장입니다.

## 2. 무엇을 만드나

주문 한 건은 다음 순서로 진행됩니다.

1. 주문이 들어오면 로봇팔이 선반에서 상품을 하나씩 집어 상자에 담습니다.
2. 다 담으면 상자를 봉인 위치로 옮깁니다.
3. 각 단계마다 세 가지 기록이 따로 남습니다.
   - 로봇 보고: 로봇이 "무엇을 집어서 상자에 담았다"고 말하는 기록
   - 외부 카메라: 로봇과 별개의 장치가 찍은 영상
   - 저울: 상자 무게
4. 서버가 세 기록을 대조해 정상인지, 문제가 있다면 원인이 무엇인지 판정합니다.
5. 주문 단위로 기록의 지문(해시)을 블록체인에 올립니다. 판매자, 물류센터, 플랫폼이 각자 노드를 갖기 때문에 한 곳이 혼자 기록을 고칠 수 없습니다. 원본 영상은 블록체인 밖에 보관합니다.

## 3. 연구 질문 (담당별)

| 담당 | 연구 질문 | 쉽게 말하면 |
|---|---|---|
| 컴퓨터비전 (RQ1) | 로봇과 독립된 카메라로 상품 집기·담기·떨어뜨림과 상자 안 상품 개수를 얼마나 정확히 확인할 수 있는가? | 카메라가 포장 과정을 증인처럼 확인할 수 있는가 |
| 로봇제어 (RQ2) | 로봇이 자기 센서(그리퍼 전류·위치)만으로 집기 실패나 떨어뜨림을 얼마나 알아채고 보고하는가? | 로봇의 "다 담았다"는 말을 어디까지 믿을 수 있는가 |
| 블록체인 (RQ3) | 어떤 기록 방식이 출고 후 수정, 물류센터 내부자의 기록 재작성, 다른 주문 영상 재사용을 막으면서 포장을 느리게 하지 않는가? | 전자서명만으로 충분한가, 블록체인이 꼭 필요한가 |
| 서버 (RQ4) | 세 기록이 서로 어긋날 때 원인을 얼마나 정확히 가려내는가? | 분쟁이 나면 누구 말이 맞는지 찾을 수 있는가 |

서버가 가려낼 원인은 다섯 가지입니다.

| 원인 | 예시 |
|---|---|
| 인식 오류 | 로봇은 이어폰을 집었다고 하는데 카메라에는 충전기가 보인다 |
| 제어 실패 | 로봇은 담았다고 하는데 카메라에 떨어지는 장면이 보이고 무게가 그대로다 |
| 거짓 보고 | 로봇은 완료라고 하는데 카메라와 저울 모두 개수가 모자란다 |
| 기록 변경 | 나중에 저장된 기록이 블록체인에 올린 지문과 다르다 |
| 외부 허위 주장 | 구매자는 누락이라고 하는데 세 기록 모두 정상으로 담겨 봉인됐다 |

## 4. 무엇을 보여 줄 것인가

검증할 가설은 세 가지입니다.

1. 카메라와 저울을 더하면, 로봇 기록만 쓸 때보다 누락·떨어뜨림·거짓 보고를 훨씬 잘 잡는다.
2. 전자서명은 서명 키를 가진 물류센터 내부자가 기록 전체를 다시 쓰면 잡지 못하지만, 블록체인은 잡는다. 판매자와 플랫폼 노드에 원래 지문이 남아 있기 때문입니다. 이것이 블록체인을 쓰는 이유입니다.
3. 주문 단위로 묶어 기록하면, 단계마다 기록할 때보다 포장이 덜 느려지고 탐지율은 거의 같다.

실험 방법은 다음과 같습니다. 아래 오류를 종류별로 30번 이상 일부러 일으키고, 정상 포장도 같은 횟수만큼 합니다. 그리고 로봇 기록만, 외부 증거 추가, 전자서명 추가, 블록체인 추가의 네 구성으로 결과를 비교합니다.

- 다른 상품 담기
- 하나 덜 담기
- 두 개 집기
- 이동 중 떨어뜨림
- 로봇의 거짓 완료 보고
- 출고 후 기록 수정
- 물류센터 내부자의 기록 재작성
- 다른 주문 영상 재사용
- 구매자의 허위 누락 신고

실험 상품은 상자형·원통형·납작한 것 등 4~6종으로 제한합니다. 그중 하나는 일부러 잡기 어려운 상품으로 골라, 집기 실패가 자연스럽게 생기게 합니다.

## 5. 하지 않는 것

- 더 좋은 인식 모델이나 집기 알고리즘을 새로 만들지 않습니다. 각 기술은 포장 과정을 확인하는 데 씁니다.
- 실제 물류센터 시스템과 연동하지 않습니다. 주문은 서버가 만들어 냅니다.
- 기록의 법적 효력이나 분쟁 처리 규정은 다루지 않습니다.

## 6. 일정과 우선순위

| 기간 | 할 일 | 다 됐다고 보는 기준 |
|---|---|---|
| 11~12월 | 역할별 환경 준비, 실험 상품 선정, 기록 형식과 오류 목록 확정 | 기록 형식 문서와 오류 목록에 4명이 합의한다 |
| 1~2월 | 담당별 단독 동작 | 집기 성공률, 인식 정확도, 블록체인 기록, 서버 판정을 각각 숫자로 보여 준다 |
| 3~4월 | 하나로 연결 | 정상 주문 한 건이 증거와 함께 기록되고 판정된다 |
| 5~6월 | 오류 주입 실험 | 네 구성 × 오류 종류별 결과표가 나온다 |
| 7월 | 결과 정리와 발표 | 보고서와 발표 자료를 제출한다 |

시간이 모자라면 아래 순서로 뒤에서부터 줄입니다.

1. 정상 포장과 증거 기록 (반드시 함)
2. 외부 증거 대조로 오류 원인 판정 (가설 1, 반드시 함)
3. 전자서명과 블록체인 비교 (가설 2, 반드시 함)
4. 구매자 허위 신고 반박 실험
5. 주문 단위와 단계 단위 기록 비교 (가설 3)
6. 다른 주문 영상 재사용 탐지
7. 판정 규칙을 학습 모델로 바꿔 비교

도메인 비교와 근거 출처는 `도메인후보_로봇팔.md`에 있습니다.

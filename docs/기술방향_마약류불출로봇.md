# 기술 방향: 마약류 의약품 불출 로봇의 행동 검증

- 확정 주제: 로봇팔이 보관함에서 마약류 앰플을 꺼내 운반함에 담는 과정에서, 로봇 자체 기록과 독립된 물리 증거를 블록체인 기록으로 묶어 기록과 실물의 불일치가 어느 단계에서 왜 생겼는지 가려낸다.
- 전제: 4명, 2027년 7월 마감. 보유 장비와 예산은 아직 모른다. 아래 장비 선택은 장비가 없다는 가정에서 정했다.
- 작성일: 2026-11-02

## 0. 연구 방향

### 핵심 연구 질문
로봇이 스스로 남긴 행동 기록을 그대로 믿을 수 없을 때, 어떤 증거를 어떻게 남기고 대조해야 여러 기관이 불출 결과와 실패 원인을 확인할 수 있는가?

### 세부 연구 질문 (분야별로 무엇을 연구하는가)

| 번호 | 분야 | 연구 질문 | 연구 대상 |
|---|---|---|---|
| RQ1 | 컴퓨터비전 | 로봇과 독립된 시각 증거로 로봇의 행동(무엇을 집었는지, 몇 개를 놓았는지, 떨어뜨렸는지)을 얼마나 정확히 확인할 수 있는가? 가림·조명 변화에서 어디까지 믿을 수 있는가? | 물체 인식이 아니라 집기·놓기·낙하 같은 행동 사건의 인식이다. 확신이 낮을 때 판정을 보류하는 기준도 포함한다. |
| RQ2 | 로봇제어 | 로봇이 자기 제어 신호(그리퍼 전류·위치, 관절 오차)만으로 자기 실패를 얼마나 감지하고 보고할 수 있는가? 자기 보고가 실제와 어긋나는 경우는 언제인가? | 실패 감지 능력과 자기 보고의 한계다. 제어 성능을 높이는 연구는 하지 않는다. |
| RQ3 | 기록·블록체인 | 어떤 기록 구조가 사후 변경, 서명 키를 가진 내부자의 위변조, 과거 증거 재사용을 막으면서 작업 지연을 감당할 만한 수준으로 유지하는가? 전자서명보다 다기관 원장이 실제로 무엇을 더 막는가? | 기록 단위(단계별, 작업별)와 기록 방식(서명, 원장)에 따른 보안과 비용의 균형이다. |
| RQ4 | 서버 | 로봇 보고, 외부 카메라, 저울이 서로 어긋날 때 오류 원인(인식 오류, 제어 실패, 거짓 보고, 기록 변경)을 얼마나 정확히 가려낼 수 있는가? | 증거를 대조하는 판정 규칙과 오류 원인 분류 체계다. |

### 가설
- H1: 외부 증거를 더하면 로봇 자체 기록만 쓸 때보다 거짓 완료 보고와 낙하의 탐지율이 크게 오른다. (RQ1, RQ2, RQ4)
- H2: 전자서명은 외부자의 기록 변경은 잡지만 키를 가진 내부자의 위변조는 잡지 못하고, 다기관 원장은 잡는다. (RQ3)
- H3: 작업 단위로 묶어 기록하면 단계마다 기록할 때보다 지연이 작고, 탐지율 차이는 작다. (RQ3)

### 기대 기여
1. 로봇 행동 검증 틀: 무엇을 증거로 남기고 어떻게 대조하는지를 정한 증거 모델과 판정 규칙
2. 오류 원인 분류 체계와 오류 주입 실험 데이터셋
3. 전자서명과 다기관 원장의 차이를 같은 조건에서 실험으로 비교한 결과

### 하지 않는 것
- 새 인식 모델이나 새 제어 알고리즘 개발
- 기록의 법적 효력, 규제 인증

## 1. 선행연구 대비 위치

| 선행연구 | 한 것 | 남긴 한계 |
|---|---|---|
| ROS 2 메시지를 블록체인에 기록하는 연구들 (Trust Chain ROS, BCubed, arXiv 2403.09567, peaq) | 로봇 통신·로그를 사후 변경할 수 없게 저장한다. | 기록이 나중에 바뀌지 않았다는 것만 보여 준다. 기록 내용이 실제 행동과 맞는지는 다루지 않는다. 연속 로그를 모두 올리면 비용이 크다는 지적도 있다. |
| RODEO (arXiv 2603.06058, ICRA 2026) | 로봇 작업 완료 증거를 검증 오라클이 확인하고 블록체인에 올린다. 검증에 약 1분 걸렸다. | 작업 완료 여부만 본다. 실패했을 때 원인이 인식인지, 제어인지, 기록인지 구분하지 않는다. |
| 약국 자동화 장비 (바코드 확인, 재계수) | 집기 전에 바코드로 약을 확인한다. | 장비가 스스로 검사한다. FDA 리콜 사례처럼 검사 센서가 틀리면 그대로 통과된다. |

우리 연구가 새로 하는 일은 두 가지다.
1. 로봇의 자기 보고와 독립된 증거(외부 카메라, 저울)를 대조해 오류 원인을 인식 오류, 제어 실패, 거짓 보고, 사후 기록 변경으로 나눈다.
2. 전자서명만으로 막을 수 없는 내부자 위변조(서명 키를 가진 기관이 기록 전체를 다시 쓰는 경우)를 여러 기관이 함께 운영하는 원장으로 막을 수 있는지 실험으로 보인다.

## 2. 시스템 구조

```
[물리 계층]  보관함(잠금·개폐 센서) ─ 로봇팔(그리퍼) ─ 운반함(아래 저울)
                    │                     │
             손목 카메라(로봇 시점)   외부 고정 카메라(독립 시점)
                    │                     │
[로봇 컴퓨터]  작업 관리·제어·로봇 자체 기록     [검증 장치: 별도 보드]  외부 카메라·저울 판정
        │  단계별 기록 + 서명(로봇 키)              │  단계별 증거 + 서명(검증 장치 키)
        └──────────────┬───────────────────────────┘
                [증거 저장소]  원본 영상·이미지 (원장 밖에 보관, 해시만 원장에 기록)
                       │
[원장]  약제부 노드 · 병동 노드 · 감독기관(모의) 노드  ── 작업 단위 요약 해시 기록, 판정 결과 기록
```

설계 원칙
- 정지·재시도 같은 안전 제어는 원장 기록을 기다리지 않는다. 기록은 작업과 따로 돌고, 원장에는 작업 단위로 묶어 올린다.
- 외부 카메라와 저울은 로봇 컴퓨터와 다른 장치에서 돌리고 키도 따로 둔다. 로봇 쪽이 잘못돼도 증거가 함께 오염되지 않게 하기 위해서다.
- 원본 영상은 원장에 올리지 않는다. 원장에는 해시와 판정 결과만 둔다.

- 작업 방식: 앰플을 정해진 거치대에 꽂아 두고, MoveIt 2로 집기·옮기기·놓기를 한다. 손목 카메라로 위치를 조금 보정한다.
- 실패 감지: 그리퍼 위치·전류로 집기 성공을 판단한다. 실패하면 멈추고 한 번 재시도한 뒤, 그래도 실패하면 사람을 부른다.
- 연구 기여 지점: 실패를 감지했을 때 로봇이 무엇을 보고하는지가 검증 대상이다. 제어 성능 자체를 높이는 연구는 하지 않는다.

### 3-2. 컴퓨터비전
- 인식 대상: 앰플 종류(캡 색·라벨이 다른 모형 4~6종), 운반함 안 수량, 그리퍼에서 떨어지는 순간.
- 모델: YOLO 계열 물체 검출로 종류와 수량을 판정하고, 추적으로 낙하를 잡는다. 라벨 글자 인식은 여유가 있을 때 추가한다.
- 데이터: 팀이 직접 촬영한 이미지 2,000~5,000장으로 시작한다. 조명과 가림 조건을 바꿔 가며 찍는다.
- 두 카메라의 역할을 나눈다. 손목 카메라는 로봇 자신의 판단 근거이고, 외부 카메라는 독립 증거다. 같은 모델을 두 카메라에 쓰되 판정은 따로 낸다.

### 3-3. 기록·블록체인
- 기록 단위: 불출 한 건을 단계로 나눈다. 처방 요청, 보관함 열기, 집기, 이동, 놓기, 운반함 봉인 순서다.
- 단계별 기록 항목: 작업 ID, 단계, 시각, 로봇 주장(집으려는 약, 그리퍼 상태, 목표 위치), 증거 해시(이미지, 무게), 이전 기록 해시, 서명.
- 장치 안에서는 각 기록이 이전 기록의 해시를 품는 사슬로 쌓는다. 작업이 끝나면 그 작업의 머클 루트를 원장에 올린다.
- 추천 원장: Hyperledger Besu 사설 네트워크(QBFT 합의, 3~4개 노드). 약제부·병동·감독기관(모의)이 각자 노드를 운영한다. Solidity와 기존 이더리움 도구를 그대로 쓸 수 있고, 거래 수수료가 없다.
- 대안: Hyperledger Fabric. 기관별 권한 관리가 더 세밀하지만 구축이 더 복잡하다. 블록체인 담당이 Fabric 경험이 있으면 이쪽을 고른다.
- 스마트컨트랙트가 할 일: 작업별 해시 등록, 판정 결과 등록, 등록 기관 확인. 판정 로직 자체는 원장 밖에서 돌린다.

### 3-4. 교차 검증 판정 (핵심 기여)
세 출처를 대조한다. 로봇 주장(R), 외부 카메라(C), 저울(W)이다. 여기에 원장 대조(L)를 더한다.

| 관찰 | 판정 |
|---|---|
| R은 A를 집었다고 하는데 C는 B를 봤다 | 로봇 인식 오류 |
| R은 놓았다고 하는데 C에서 낙하가 보이고 W가 그대로다 | 제어 실패(낙하) |
| R은 완료라고 하는데 C·W 모두 수량이 모자라고 낙하도 없다 | 거짓 완료 보고 |
| 저장된 기록의 해시가 원장의 해시와 다르다 | 사후 기록 변경 |
| 증거 이미지 해시가 이전 작업과 같거나 시각이 맞지 않는다 | 과거 증거 재사용 |
| C와 W가 서로 다르다 | 센서 이상, 판정 보류 |

규칙 기반으로 시작한다. 시간이 남으면 판정을 학습 모델로 바꿔 비교한다.

## 4. 실험 설계

### 주입할 오류 (각 30회 이상, 정상 작업도 같은 수)
1. 다른 종류 앰플 집기
2. 이동 중 낙하
3. 두 개 집기
4. 놓기 실패
5. 거짓 완료 보고(로봇 보고만 조작)
6. 작업 후 기록 수정
7. 서명 키를 가진 한 기관이 기록 전체를 다시 쓰고 다시 서명(내부자 위변조)
8. 이전 작업 영상 재사용

### 비교 구성

| 구성 | 증거 | 저장 |
|---|---|---|
| 1 | 로봇 자체 기록만 | 일반 데이터베이스 |
| 2 | 로봇 기록 + 외부 카메라·저울 | 일반 데이터베이스 |
| 3 | 2와 같음 | 전자서명 해시 사슬 |
| 4 | 2와 같음 | 다기관 원장(Besu) |

예상하는 결과는 다음과 같다. 1과 2를 비교하면 오류 1~5에서 독립 증거가 얼마나 필요한지 보인다. 2와 3을 비교하면 오류 6에서 서명의 효과가 보인다. 3과 4를 비교하면 오류 7에서 원장이 무엇을 더 막는지 보인다.

### 측정값
- 오류 유형 판정 정확도와 F1, 오탐률
- 위변조 탐지율
- 작업 한 건당 추가 지연(로봇 작업 시간 대비)
- 작업 한 건당 저장량, 원장 기록 시간

## 7. 한계와 범위 밖
- 기록하는 순간 카메라 영상 자체를 바꿔 넣는 공격은 막지 못한다. 서로 다른 두 증거(카메라, 저울)를 대조해 일부만 줄인다.
- 실제 마약류는 쓰지 않는다. 모형 앰플을 쓴다.
- 법적 증거 효력이나 규제 인증은 다루지 않는다.

## 8. 확인하지 못한 것
- OpenMANIPULATOR-X 국내 판매가와 구성품, 팔 외 장비 가격
- 로드셀로 모형 개수를 실제로 판별할 수 있는지(첫 달 시험으로 확인)
- RODEO 논문 원문의 증거 형식과 검증 방법(초록과 일부 본문만 확인)
- 선행연구는 웹 검색으로 찾은 범위만 대조했다. 학술 데이터베이스 검색은 하지 않았다.

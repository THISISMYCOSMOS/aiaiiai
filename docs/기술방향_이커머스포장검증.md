# 기술 방향: 이커머스 주문 포장 로봇의 행동 검증

- 확정 주제: 로봇팔이 주문 상품을 집어 상자에 담고 봉인하는 과정에서, 로봇 자체 기록과 독립된 물리 증거(외부 카메라, 저울)를 블록체인 기록으로 묶는다. 이를 통해 누락·오배송이 어느 단계에서 왜 생겼는지, 분쟁에서 누구의 말이 맞는지 가려낸다.
- 전제: 4명, 2027년 7월 마감. 쓸 수 있는 로봇은 로봇팔과 그리퍼뿐이다. 로봇팔은 아직 없고 구매할 예정이다.
- 작성일: 2026-11-04 (마약류 불출 로봇 기준의 이전 문서 `기술방향_마약류불출로봇.md`를 도메인만 바꿔 다시 썼다)

## 0. 연구 방향

### 핵심 연구 질문
로봇이 스스로 남긴 포장 기록을 그대로 믿을 수 없을 때, 어떤 증거를 어떻게 남기고 대조해야 판매자·물류센터·플랫폼이 포장 결과와 실패 원인을 함께 확인할 수 있는가?

### 세부 연구 질문

| 번호 | 분야 | 연구 질문 | 연구 대상 |
|---|---|---|---|
| RQ1 | 컴퓨터비전 | 로봇과 독립된 카메라로 로봇의 행동(어떤 상품을 집었는지, 상자에 몇 개를 담았는지, 떨어뜨렸는지)을 얼마나 정확히 확인할 수 있는가? 상자 안에서 상품이 겹쳐 가려질 때 어디까지 믿을 수 있는가? | 물체 인식이 아니라 집기·담기·낙하 같은 행동 사건의 인식이다. 확신이 낮을 때 판정을 보류하는 기준도 포함한다. |
| RQ2 | 로봇제어 | 로봇이 자기 제어 신호(그리퍼 전류·위치, 관절 오차)만으로 집기 실패와 떨어뜨림을 얼마나 감지하고 보고할 수 있는가? 자기 보고가 실제와 어긋나는 경우는 언제인가? | 실패 감지 능력과 자기 보고의 한계다. 제어 성능을 높이는 연구는 하지 않는다. |
| RQ3 | 기록·블록체인 | 어떤 기록 구조가 출고 후 수정, 서명 키를 가진 물류센터 내부자의 기록 재작성, 다른 주문 영상 재사용을 막으면서 포장 지연을 감당할 만한 수준으로 유지하는가? 전자서명보다 다기관 원장이 실제로 무엇을 더 막는가? | 기록 단위(단계별, 주문별)와 기록 방식(서명, 원장)에 따른 보안과 비용의 균형이다. |
| RQ4 | 서버 | 로봇 보고, 외부 카메라, 저울이 서로 어긋날 때 원인(인식 오류, 제어 실패, 거짓 보고, 기록 변경, 외부 허위 주장)을 얼마나 정확히 가려낼 수 있는가? | 증거를 대조하는 판정 규칙과 원인 분류 체계다. |

### 가설
- H1: 외부 증거를 더하면 로봇 자체 기록만 쓸 때보다 누락, 떨어뜨림, 거짓 완료 보고의 탐지율이 크게 오른다. (RQ1, RQ2, RQ4)
- H2: 전자서명은 외부자의 기록 변경은 잡지만, 키를 가진 물류센터 내부자의 기록 재작성은 잡지 못한다. 다기관 원장은 판매자·플랫폼 노드에 원래 지문이 남아 있어 잡는다. (RQ3)
- H3: 주문 단위로 묶어 기록하면 단계마다 기록할 때보다 지연이 작고, 탐지율 차이는 작다. (RQ3)

### 기대 기여
1. 포장 행동 검증 틀: 무엇을 증거로 남기고 어떻게 대조하는지를 정한 증거 모델과 판정 규칙
2. 원인 분류 체계와 오류 주입 실험 데이터셋
3. 전자서명과 다기관 원장의 차이를 같은 조건에서 실험으로 비교한 결과
4. 외부 허위 주장(구매자의 허위 누락 신고)을 증거로 반박할 수 있는지에 대한 실험 결과

### 하지 않는 것
- 새 인식 모델이나 새 집기 알고리즘 개발
- 실제 물류센터 관리 시스템과 연동
- 기록의 법적 효력, 분쟁 처리 규정

## 1. 선행연구와 현행 방식 대비 위치

| 선행연구·현행 방식 | 한 것 | 남긴 한계 |
|---|---|---|
| ROS 2 메시지를 블록체인에 기록하는 연구들 (Trust Chain ROS, BCubed, arXiv 2403.09567, peaq) | 로봇 통신·로그를 사후 변경할 수 없게 저장한다. | 기록이 나중에 바뀌지 않았다는 것만 보여 준다. 기록 내용이 실제 행동과 맞는지는 다루지 않는다. 연속 로그를 모두 올리면 비용이 크다는 지적도 있다. |
| RODEO (arXiv 2603.06058, ICRA 2026) | 로봇 작업 완료 증거를 검증 오라클이 확인하고 블록체인에 올린다. 검증에 약 1분 걸렸다. | 작업 완료 여부만 본다. 실패했을 때 원인이 인식인지, 제어인지, 기록인지 구분하지 않는다. |
| 현행 분쟁 대응 (판매자 포장 영상, 송장 무게, 출고 기록) | 영상과 무게를 분쟁 증거로 쓴다. | 기록을 만든 쪽이 보관하고 고칠 수 있다. 실제로 "찍은 뒤에 뺐을 수 있다"는 반론이 나온다. |

우리 연구가 새로 하는 일은 세 가지다.
1. 로봇의 자기 보고와 독립된 증거(외부 카메라, 저울)를 대조해 원인을 인식 오류, 제어 실패, 거짓 보고, 사후 기록 변경으로 나눈다.
2. 전자서명만으로 막을 수 없는 내부자 위변조를 여러 기관이 함께 운영하는 원장으로 막을 수 있는지 실험으로 보인다.
3. 같은 증거로 외부의 허위 주장까지 반박할 수 있는지 보인다.

## 2. 시스템 구조

```
[물리 계층]  상품 선반(칸별 상품) ─ 로봇팔(그리퍼) ─ 포장 상자(아래 저울) ─ 봉인 위치
                    │                     │
             손목 카메라(로봇 시점)   외부 고정 카메라(독립 시점)
                    │                     │
[로봇 컴퓨터]  주문 처리·제어·로봇 자체 기록     [검증 장치: 별도 보드]  외부 카메라·저울 판정
        │  단계별 기록 + 서명(로봇 키)              │  단계별 증거 + 서명(검증 장치 키)
        └──────────────┬───────────────────────────┘
                [서버]  증거 수집, 원본 영상 보관, 교차 검증 판정
                       │
[원장]  판매자 노드 · 물류센터 노드 · 플랫폼 노드  ── 주문 단위 요약 해시 기록, 판정 결과 기록
                       │
             구매자·판매자는 플랫폼을 거쳐 주문별 증거와 판정을 조회
```

설계 원칙
- 집기 실패 시 정지·재시도 같은 제어는 원장 기록을 기다리지 않는다. 기록은 작업과 따로 돌고, 원장에는 주문 단위로 묶어 올린다.
- 외부 카메라와 저울은 로봇 컴퓨터와 다른 장치에서 돌리고 키도 따로 둔다. 로봇 쪽이 잘못돼도 증거가 함께 오염되지 않게 하기 위해서다.
- 원본 영상은 원장에 올리지 않는다. 원장에는 해시와 판정 결과만 둔다.
- 실험에서 물류센터 노드와 로봇·검증 장치 키는 같은 기관(물류센터)이 가진 것으로 본다. 그래야 내부자 위변조 실험이 현실과 맞는다.

## 3. 파트별 기술 결정

### 3-1. 로봇제어
- 작업 순서: 주문을 받으면 상품 칸에서 상품을 하나씩 집어 상자에 담는다. 다 담으면 봉인 단계로 넘어간다. 봉인은 로봇이 뚜껑을 덮는 동작으로 하고, 어려우면 봉인 버튼을 누른 시점을 기록하는 방식으로 대신한다.
- 상품은 정해진 칸에 놓아 두고 MoveIt 2로 집기·옮기기·담기를 한다. 손목 카메라로 위치를 조금 보정한다.
- 실패 감지: 그리퍼 위치·전류로 집기 성공을 판단한다. 실패하면 멈추고 한 번 재시도한 뒤, 그래도 실패하면 사람을 부른다.
- 연구 기여 지점: 실패를 감지했을 때 로봇이 무엇을 보고하는지가 검증 대상이다. 집기 성능을 높이는 연구는 하지 않는다.

### 3-2. 컴퓨터비전
- 인식 대상: 집은 상품의 종류, 상자에 들어간 순간, 그리퍼에서 떨어지는 순간, 상자 안 상품 개수.
- 상자 안 개수는 상품이 겹쳐 가려지기 쉽다. 그래서 최종 사진 한 장으로 세지 않고, 담을 때마다 담기 전과 후를 비교해 하나씩 더해 가는 방식을 기본으로 한다. 최종 사진은 보조 증거로 쓴다.
- 모델: YOLO 계열 물체 검출로 종류를 판정하고, 추적으로 담기·낙하를 잡는다.
- 데이터: 팀이 직접 촬영한 이미지 2,000~5,000장으로 시작한다. 조명, 가림, 상품 배치를 바꿔 가며 찍는다.
- 두 카메라의 역할을 나눈다. 손목 카메라는 로봇 자신의 판단 근거이고, 외부 카메라는 독립 증거다. 같은 모델을 쓰되 판정은 따로 낸다.

### 3-3. 기록·블록체인
- 기록 단위: 주문 한 건을 단계로 나눈다. 주문 접수, 상품별 집기, 상품별 담기, 봉인, 출고 순서다.
- 단계별 기록 항목: 주문 ID, 단계, 시각, 로봇 주장(집으려는 상품, 그리퍼 상태, 목표 위치), 증거 해시(이미지, 무게), 이전 기록 해시, 서명.
- 장치 안에서는 각 기록이 이전 기록의 해시를 품는 사슬로 쌓는다. 주문이 끝나면 그 주문의 머클 루트를 원장에 올린다.
- 추천 원장: Hyperledger Besu 사설 네트워크(QBFT 합의, 3~4개 노드). 판매자·물류센터·플랫폼이 각자 노드를 운영한다. Solidity와 기존 이더리움 도구를 그대로 쓸 수 있고, 거래 수수료가 없다.
- 대안: Hyperledger Fabric. 기관별 권한 관리가 더 세밀하지만 구축이 더 복잡하다.
- 스마트컨트랙트가 할 일: 주문별 해시 등록, 판정 결과 등록, 분쟁 신고 등록, 등록 기관 확인. 판정 로직 자체는 서버에서 돌린다.

### 3-4. 교차 검증 판정 (서버, 핵심 기여)
세 출처를 대조한다. 로봇 주장(R), 외부 카메라(C), 저울(W)이다. 여기에 원장 대조(L)와 구매자 신고(D)를 더한다.

| 관찰 | 판정 |
|---|---|
| R은 상품 A를 집었다고 하는데 C는 상품 B를 봤다 | 로봇 인식 오류 |
| R은 담았다고 하는데 C에서 낙하가 보이고 W가 그대로다 | 제어 실패(낙하) |
| R은 완료라고 하는데 C·W 모두 개수가 모자라고 낙하도 없다 | 거짓 완료 보고 |
| 저장된 기록의 해시가 원장의 해시와 다르다 | 사후 기록 변경 |
| 증거 이미지 해시가 다른 주문과 같거나 시각이 맞지 않는다 | 다른 주문 증거 재사용 |
| D는 누락이라고 하는데 R·C·W와 원장이 모두 정상 포장·봉인을 가리킨다 | 외부 허위 주장 가능성 (봉인 이후 구간은 판단 밖) |
| C와 W가 서로 다르다 | 센서 이상, 판정 보류 |

규칙 기반으로 시작한다. 시간이 남으면 판정을 학습 모델로 바꿔 비교한다. 봉인 이후 배송 구간에서 생긴 일은 이 시스템이 판단하지 않는다는 점을 판정 결과에 함께 남긴다.

## 4. 실험 설계

### 주입할 오류 (각 30회 이상, 정상 포장도 같은 수)
1. 다른 상품 담기
2. 하나 덜 담기
3. 두 개 집기
4. 이동 중 떨어뜨림
5. 로봇의 거짓 완료 보고(로봇 보고만 조작)
6. 출고 후 기록 수정
7. 물류센터 내부자가 서명 키로 기록 전체를 다시 쓰고 다시 서명
8. 다른 주문 영상 재사용
9. 구매자의 허위 누락 신고(실제로는 정상 포장)

### 비교 구성

| 구성 | 증거 | 저장 |
|---|---|---|
| 1 | 로봇 자체 기록만 | 일반 데이터베이스 |
| 2 | 로봇 기록 + 외부 카메라·저울 | 일반 데이터베이스 |
| 3 | 2와 같음 | 전자서명 해시 사슬 |
| 4 | 2와 같음 | 다기관 원장(Besu) |

예상하는 결과는 다음과 같다. 1과 2를 비교하면 오류 1~5에서 독립 증거가 얼마나 필요한지 보인다. 2와 3을 비교하면 오류 6에서 서명의 효과가 보인다. 3과 4를 비교하면 오류 7에서 원장이 무엇을 더 막는지 보인다. 오류 9는 구성마다 허위 신고를 얼마나 반박할 수 있는지로 비교한다.

### 측정값
- 원인 판정 정확도와 F1, 오탐률
- 위변조 탐지율
- 주문 한 건당 추가 지연(로봇 포장 시간 대비)
- 주문 한 건당 저장량, 원장 기록 시간

## 5. 역할

| 역할 | 맡는 일 | 산출물 |
|---|---|---|
| 로봇제어 | 팔 구동, 집기·담기·봉인, 실패 감지와 보고 | ROS 2 제어 노드, 집기 성공률 측정 |
| 컴퓨터비전 | 데이터 수집, 상품 종류·담기·낙하·개수 인식 | 손목·외부 시점 모델, 인식 정확도 |
| 블록체인 | 기록 형식, 서명, Besu 네트워크, 컨트랙트 | 원장 네트워크, 기록·검증 도구 |
| 서버 | 주문 생성, 증거 수집·보관, 교차 검증 판정, 오류 주입, 분석 | 판정 모듈, 실험 결과 |

## 6. 일정 (2026-11 ~ 2027-07)

| 기간 | 할 일 | 끝났다고 보는 기준 |
|---|---|---|
| 11~12월 | 장비 확정·구매, 실험 상품 선정, ROS 2 환경, 기록 형식과 오류 목록 확정, 데이터 촬영 시작 | 팔이 ROS 2에서 정해진 자세로 움직이고, 저울이 상품 하나 차이를 구분한다 |
| 1~2월 | 파트별 단독 동작 | 집기 성공률, 인식 정확도, 원장 기록 동작, 서버 판정을 각각 숫자로 확인한다 |
| 3~4월 | 통합과 교차 검증 판정 | 정상 주문 한 건이 증거와 함께 원장에 기록되고 판정된다 |
| 5~6월 | 오류 주입 실험과 비교 | 구성 4개 × 오류 9종 결과표가 나온다 |
| 7월 | 결과 정리, 발표·보고서 | 최종 산출물 제출 |

시간이 모자라면 뒤에서부터 줄인다. 순서는 기획안과 같다. 정상 포장과 증거 기록, 가설 1, 가설 2는 반드시 하고, 그다음 허위 신고 반박, 가설 3, 영상 재사용 탐지, 학습 기반 판정 순으로 줄인다.

## 7. 한계와 범위 밖
- 기록하는 순간 카메라 영상 자체를 바꿔 넣는 공격은 막지 못한다. 서로 다른 두 증거(카메라, 저울)를 대조해 일부만 줄인다.
- 봉인 이후 배송 중에 생긴 분실·바꿔치기는 판단하지 않는다.
- 상품은 4~6종으로 제한한다. 실제 물류센터의 수많은 상품 종류로 넓히는 것은 범위 밖이다.
- 법적 증거 효력이나 분쟁 처리 규정은 다루지 않는다.

## 8. 확인하지 못한 것
- 로봇팔 국내 판매가와 구성품, 팔 외 장비 가격
- 로드셀로 상품 하나 차이를 실제로 구분할 수 있는지(첫 달 시험으로 확인)
- 상자 안에서 상품이 겹칠 때 외부 카메라로 개수를 셀 수 있는 한계(데이터 촬영 단계에서 확인)
- RODEO 논문 원문의 증거 형식과 검증 방법(초록과 일부 본문만 확인)
- 선행연구는 웹 검색으로 찾은 범위만 대조했다. 학술 데이터베이스 검색은 하지 않았다.
